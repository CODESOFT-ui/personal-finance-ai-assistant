# Personal Finance RAG Agent — Guardrails + Evaluation

A Retrieval-Augmented Generation assistant over a **personal-finance knowledge base**, built with **LangGraph**, **ChromaDB**, **OpenAI embeddings**, a three-layer **guardrail** pipeline, and an automatic **RAG evaluation** module (search metrics, answer metrics, and an LLM-as-a-judge).

> Assignment 4 (AI AMC Batch 5.0 — Joseph). Adapted from the `RAG_AI_Agent` teaching repo to a **personal finance / financial-literacy** domain with my own PDF documents. See **[REPORT.md](REPORT.md)** for the write-up, settings I tuned, and test results.

## Domain & documents

Four original financial-literacy PDFs (in `data/`, generated by `data/build_pdfs.py`, so no copyrighted material):

| File | Covers |
|------|--------|
| `01_budgeting_and_saving.pdf` | 50/30/20 rule, emergency funds, zero-based budgeting, sinking funds, inflation |
| `02_investing_basics.pdf` | compound interest, diversification, index funds, risk/return, dollar-cost averaging, retirement |
| `03_banking_and_credit.pdf` | account types, credit cards, credit scores, loan rates, digital payments, deposit insurance |
| `04_fraud_and_account_security.pdf` | phishing, 2FA, passwords, card skimming, identity theft, investment scams |

## Architecture

```
PDFs ─ ingestion.py ─▶ chunks + OpenAI embeddings ─▶ Chroma vector DB

User question
  ─▶ regex input guard   (block attacks; redact PII incl. card numbers)
  ─▶ NLP input guard     (is this really a personal-finance question?)
  ─▶ understand_question ─▶ search_index (retrieve TOP_K chunks)
        ├─▶ budgeting_specialist  ┐
        ├─▶ investing_specialist  ┤ (parallel)
        └─▶ safety_specialist     ┘
  ─▶ pick_response_mode  (quick vs detailed)
  ─▶ quick_answer / detailed_answer
  ─▶ guardrail_agent     (approve / modify / block the draft)
  ─▶ regex output guard  ─▶ NLP output guard
  ─▶ evaluate_response   (LLM-as-judge on a DIFFERENT model)
  ─▶ deliver_response (cited answer + safety notes + eval summary)
```

The three parallel specialists (budgeting / investing / account-security) each read the same retrieved context from a different angle, then a planner node routes to a quick or detailed answer.

## What I changed from the reference project

- **Domain:** health/fitness → **personal finance**. Specialists renamed to `budgeting_specialist`, `investing_specialist`, `safety_specialist`; every prompt, guard rule, and demo scenario rewritten for finance (e.g. the input guard now blocks *get-rich-quick / off-topic* queries; PII redaction includes **card numbers**, which is on-theme).
- **Own data:** four original finance PDFs.
- **Embeddings:** local HuggingFace MiniLM → **OpenAI `text-embedding-3-small`** (no PyTorch needed).
- **Different judge model:** the generator is `gpt-4o-mini`; the **LLM-as-judge is `gpt-4.1-mini`** — deliberately different, per the assignment rule *"don't grade an answer with the same model that wrote it."*
- **Tuned settings (2):** `TOP_K` 4 → 5 (retrieval); `CHUNK_SIZE/OVERLAP` 1000/200 → 800/150 (chunking). See REPORT.md.

## Setup

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env          # add OPENAI_API_KEY
```

`.env` keys: `OPENAI_API_KEY`, optional `LLM_MODEL` (generator, default `gpt-4o-mini`) and `JUDGE_MODEL` (evaluator, default `gpt-4.1-mini`).

## Run

```powershell
python ingestion.py            # build the vector DB from the PDFs in data/
python main.py                 # interactive guarded RAG chat
# or run the guarded graph directly (audit trail + `demo` mode):
python guardrails_rag_graph.py
# or just the core teaching agent (no guards):
python rag_agent.py
```

In `guardrails_rag_graph.py`, type `demo` to run 10 guardrail scenarios (clean query, PII redaction incl. card number, prompt-/SQL-injection blocks, off-topic block).

## Evaluation

`evaluate_response` runs inside the graph after the guards pass:
- **LLM-as-judge** (`gpt-4.1-mini`) scores **groundedness, claim precision, hallucination count, relevancy** against the retrieved sources — it runs online because it only needs the answer and its sources.
- **Answer metrics** (ROUGE, fuzzy, semantic) run when a reference answer is supplied.
- **Search metrics** (MRR, MAP, precision, recall, F1, NDCG) are in the `rag_evaluator` package and demonstrated by:

```powershell
pip install -e .                 # makes `rag_evaluator` importable anywhere
python examples/run_evaluation.py
```

The full metrics reference is in the `rag_evaluator` package.

## Verified results (see REPORT.md)

- Ingestion: 4 PDFs → 12 chunks.
- Query *"How should I build an emergency fund and how big should it be?"* → detailed answer grounded in the budgeting PDF with citations; judge: claim precision 100%, hallucinations 0, relevancy 1.00.
- Off-topic query (*"best workout routine"*) → blocked by the NLP input guard.
- `python examples/run_evaluation.py` → MRR 1.0, MAP 0.7, precision 0.4, recall 1.0, F1 0.57, NDCG 0.89, plus ROUGE/fuzzy/semantic.
- **33/33 tests pass** (`pytest`).
